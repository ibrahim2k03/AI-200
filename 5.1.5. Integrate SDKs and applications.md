Integrating Azure Database for PostgreSQL into your applications requires choosing appropriate client libraries, managing connections effectively, and handling errors gracefully. This unit covers SDK integration patterns for Python, along with best practices that apply across programming languages and application architectures.

 Note

Code examples in this unit demonstrate patterns for integrating PostgreSQL with your applications. The psycopg library (version 3) is recommended PostgreSQL adapter for Python. Visit the psycopg documentation for the most current API details and best practices.

Client library selection
Choose the right PostgreSQL client library based on your application's requirements:

psycopg (version 3): The most widely used PostgreSQL adapter for Python
- Provides both synchronous and asynchronous interfaces
- Supports connection pooling, server-side prepared statements, and full PostgreSQL feature support
- Compatible with Python 3.8+ and PostgreSQL 12+
- Well-documented with extensive community support and regular updates
- Includes built-in support for JSON data types, array operations, and COPY commands

asyncpg (version 3): Asynchronous PostgreSQL adapter
- Suitable for high-concurrency applications with I/O-bound workloads
- Provides async/await interface for Python 3.10+
- Uses same underlying protocol as psycopg but with different connection management
- Good choice when you need to execute many queries concurrently

psycopg2 (version 2): Legacy PostgreSQL adapter with limited feature support
- Maintained for compatibility with older PostgreSQL versions
- Consider only if your application needs to connect to PostgreSQL 11 or earlier environments

SQLAlchemy (ORM): High-level object-relational mapper
- Provides database-agnostic interface that works with multiple PostgreSQL backends
- Includes connection pooling, session management, and ORM features
- Good choice for complex applications with many models and relationships
- Adds abstraction layer that can simplify database operations

Django ORM: Web framework with PostgreSQL backend
- Built-in PostgreSQL integration with connection pooling and ORM features
- Good choice for web applications that need to manage user authentication, sessions, and database migrations
- Includes admin interface for database management

FastAPI: Modern async web framework
- Native async/await support with PostgreSQL databases
- Pydantic integration for data validation and serialization
- Good choice for building modern APIs with PostgreSQL backends

Connection management strategies
Effective connection management improves application reliability and performance regardless of programming language:

Context managers ensure connections are properly closed
- Connection pools reduce overhead of establishing new connections
- Always use context managers (with statements) to guarantee proper cleanup, even when exceptions occur

Connection pooling configuration
Configure appropriate pool sizes based on your application's concurrency requirements
- Set max connections to match your expected peak load
- Use appropriate pool modes (session vs. transaction) for your application's query patterns
- Monitor pool utilization and adjust sizes based on actual usage

Error handling and logging
Implement comprehensive error handling for database operations
- Catch specific exceptions like OperationalError, DatabaseError, and NetworkError
- Log detailed error information including timestamps and user context
- Use structured logging to track application performance and troubleshoot issues

## Python integration patterns

### psycopg (version 3) connection management

#### Basic connection pattern

##### Python
```python
import psycopg
from psycopg_pool import ConnectionPool

# Connection pool configuration
pool = ConnectionPool(
    minconn=1,
    maxconn=10,
    connection_string="postgresql://user:password@host/dbname"
)

# Use connection from pool
with pool.connection() as conn:
    with conn.cursor() as cur:
        cur.execute("SELECT * FROM users WHERE id = %s", (user_id,))
        user = cur.fetchone()
```

#### Asynchronous connection pattern

##### Python
```python
import asyncio
```

### SQLAlchemy ORM integration

#### Python
```python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

# Create engine and session
engine = create_engine("postgresql://user:password@host/dbname")
SessionLocal = sessionmaker(bind=engine)

# Use ORM for database operations
with SessionLocal() as session:
    user = session.query(User).filter(User.id == user_id).first()
    user.name = "Updated Name"
    session.commit()
```

### FastAPI with PostgreSQL

#### Python
```python
from fastapi import FastAPI
from sqlalchemy import create_engine
import asyncpg
import psycopg

# Async database connection
engine = create_async_engine("postgresql+asyncpg://user:password@host/dbname")

# FastAPI application
app = FastAPI()

@app.get("/users/{user_id}")
async def get_user(user_id: int):
    async with asyncpg.connect("postgresql://user:password@host/dbname") as conn:
        async with conn.cursor() as cur:
            await cur.execute("SELECT * FROM users WHERE id = %s", (user_id,))
            user = await cur.fetchone()
    return user
```

### Connection string management

#### Store in Azure Key Vault for production

##### Python
```python
import os
from azure.keyvault.secrets import SecretClient
from psycopg import connect

# Retrieve connection string from Key Vault
key_vault_client = SecretClient(vault_url="https://myvault.vault.azure.net/")
connection_string = key_vault_client.get_secret("postgres-connection-string").value

# Connect using retrieved connection string
conn = connect(connection_string)
```

#### Use environment variables for flexible configuration

##### Python
```python
import os
from psycopg import connect

# Use environment variables for different environments
dev_conn_string = os.getenv("DEV_DB_CONN")
prod_conn_string = os.getenv("PROD_DB_CONN")

conn = connect(dev_conn_string if os.getenv("ENV") == "dev" else prod_conn_string)
```

## Best practices

### Use environment-specific configurations

- Development: Use local PostgreSQL, verbose logging, and shorter connection timeouts
- Testing: Use separate test database with realistic data volumes
- Production: Use Azure Database for PostgreSQL with connection pooling, SSL/TLS, and appropriate security settings

### Implement health checks

- Monitor connection pool status and database availability
- Implement circuit breakers to prevent cascading failures
- Use retry logic with exponential backoff for transient failures

### Security considerations

- Always use SSL/TLS in production environments
- Implement proper authentication and authorization
- Use parameterized queries to prevent SQL injection
- Store connection strings securely using Azure Key Vault or environment variables
