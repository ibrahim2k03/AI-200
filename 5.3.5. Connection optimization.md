Database connections are expensive resources that significantly impact application performance and scalability. Efficient connection management reduces latency, improves throughput, and prevents resource exhaustion. This unit covers connection pooling, timeout configuration, retry strategies, and monitoring approaches for AI applications with high database usage.

 Note

Code examples in this unit demonstrate connection management patterns for Python (psycopg) and .NET (Npgsql). These libraries are updated frequently. Visit the official documentation for current API details and best practices.

Connection overhead analysis
Each database connection involves multiple steps that contribute to overall latency:

Network round trip: 1-3 milliseconds for local networks, 10-100ms for cloud networks
TLS handshake: 1-2 milliseconds for establishing secure connection
Authentication: 50-200 milliseconds depending on method (password vs. token-based)
Server process allocation: 1-5 milliseconds for PostgreSQL to spawn backend process
Session initialization: 5-10 milliseconds for setting up session parameters
Query execution: 2-50 milliseconds for simple queries, 100+ milliseconds for complex vector searches
Result serialization: 1-5 milliseconds per 1,000 rows of data

For AI applications making thousands of vector queries per minute, connection overhead can become the primary bottleneck. Reducing connections per query from 10 to 1 provides a 10x performance improvement.

Connection pooling with PgBouncer
PgBouncer maintains a pool of database connections that applications can reuse. This eliminates the overhead of establishing new connections for each query.

Key benefits:
- Reduces connection overhead from 50-200ms to 5-10ms per query
- Manages concurrent connections efficiently
- Provides connection limits and timeout handling
- Integrates with Azure Database for PostgreSQL automatically

Pool configuration parameters:
max_client_conn: Maximum connections per pool (default: 100)
default_pool_size: Connections to maintain when idle (default: 20)
min_pool_size: Minimum connections to keep ready (default: 0)
max_idle_time: Close connections after this many seconds idle (default: 600)
max_lifetime: Maximum connection lifetime (default: 3600)
pool_mode: How connections are used (session, transaction, statement)
server_reset_query: Reset connection state between queries
server_reset_delay: Delay after server reset
query_wait_timeout: Time to wait for query results
query_timeout: Maximum query execution time
Application-level pooling
For applications with multiple independent database connections, implement your own connection pool to manage resources across different databases or services.

Python connection pool example:
```python
from psycopg_pool import ConnectionPool

# Create a global pool
pool = ConnectionPool(
    minconn=5,
    maxconn=50,
    max_idle=300,
    max_lifetime=3600,
    connection_string="postgresql://user:password@host/dbname"
)

# Use the pool in your application
def get_database_connection():
    return pool.connection()

# Close connections when done
def release_connection(conn):
    conn.close()
    pool.putconn(conn)
```

Connection string optimization
Use connection strings that disable unnecessary features to reduce overhead:

- disable_prepared_statements: Reduces server round trips for query planning
- application_name: Identifies your application for monitoring
- connect_timeout: Prevents hanging connections
- tcp_keepalive: Maintains connection health
- sslmode: Configure appropriate SSL level

Example optimized connection string:
```
postgresql://user:password@host/dbname?application_name=myapp&connect_timeout=30&tcp_keepalive=60&sslmode=require&disable_prepared_statements=on
```

Timeout configuration
Set appropriate timeouts based on your workload characteristics:

- connect_timeout: Maximum time to establish connection (default: 30 seconds)
- query_timeout: Maximum query execution time (default: 30 seconds)
- statement_timeout: Maximum statement execution time (default: 30 seconds)
- tcp_keepalives: Keep connection alive during inactivity
- idle_in_transaction_session_timeout: Close idle transactions

For vector search applications:
- Set longer query timeouts (60-300 seconds) to accommodate complex similarity calculations
- Use statement_timeout for bulk operations (COPY command)
- Set tcp_user_timeout to prevent long-running queries from blocking others

Retry strategies
Implement robust retry logic for transient failures:

Exponential backoff:
```python
import time
import random

def retry_with_backoff(func, max_retries=5, base_delay=1):
    for attempt in range(max_retries):
        try:
            return func()
        except OperationalError as e:
            if attempt < max_retries - 1:
                wait_time = base_delay * (2 ** attempt)
                time.sleep(wait_time)
            else:
                wait_time = base_delay * (2 ** (attempt - 1))
            time.sleep(wait_time)
        except Exception as e:
            # Log error and continue
            print(f"Attempt {attempt + 1} failed: {e}")
            time.sleep(base_delay * 4)  # Exponential backoff
    raise Exception("Max retries exceeded")
```

Jitter:
```python
import random

def retry_with_jitter(func, max_retries=5):
    for attempt in range(max_retries):
        try:
            return func()
        except OperationalError as e:
            if attempt < max_retries - 1:
                wait_time = random.uniform(0.5, 2.0)  # Random jitter
                time.sleep(wait_time)
            else:
                wait_time = random.uniform(0.5, 4.0)
            time.sleep(wait_time)
        except Exception as e:
            print(f"Attempt {attempt + 1} failed: {e}")
            time.sleep(base_delay * 4)
    raise Exception("Max retries exceeded")
```

Circuit breaker pattern:
```python
import time

class CircuitBreaker:
    def __init__(self, failure_threshold=5, timeout=60):
        self.failure_count = 0
        self.last_failure_time = None
        self.state = 'closed'
    
    def call(self, func):
        if self.state == 'open':
            try:
                result = func()
                self.failure_count = 0
                self.state = 'closed'
                return result
            except Exception as e:
                self.failure_count += 1
                self.last_failure_time = time.time()
                self.state = 'open'
                raise e
    
    def reset(self):
        self.failure_count = 0
        self.state = 'closed'
        self.last_failure_time = None

# Usage
breaker = CircuitBreaker()

def database_query(query):
    try:
        return breaker.call(execute_query, query)
    except OperationalError as e:
        print(f"Database query failed: {e}")
        return None
```

Connection health monitoring
Monitor connection pool health and performance metrics:

Python
```python
import psycopg
```
